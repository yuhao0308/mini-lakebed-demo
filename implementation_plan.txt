# Mini-Lakebed Demo MVP: Inventory Q&A + Payment Estimates

End-to-end implementation plan for a governed agentic AI demo running on **Mac mini M4** with **$0 budget**. This plan covers both (A) Inventory Q&A and (B) Payment Estimates using approved lender rules only.

---

## 0) Operating Constraint: Decision Framework

| Decision Point | Options | This Plan |
|---|---|---|
| LLM | Local (Ollama) vs Free Cloud (Gemini/Groq) | **Local-first** |
| Database | SQLite vs Postgres | **Local-first (SQLite)** |
| Embeddings | Local (Nomic/all-MiniLM) vs Cloud | **Local-first** |
| Vector Store | FAISS/Chroma vs Pinecone Free | **Local-first (ChromaDB)** |
| Backend | Python FastAPI local | **Local-first** |
| Frontend | React/Vite local dev | **Local-first** |

> [!NOTE]
> **Rationale**: Mac mini M4 has excellent local ML performance (Neural Engine + unified memory). Local-first minimizes latency, eliminates API costs, and allows offline development. Fallbacks documented per section.

## 1) Combined Demo Scope

### 1.1 What We WILL Demo

#### Option A: Inventory Q&A
- Search vehicles by make, model, year, price range, body style, color
- Filter by specific attributes (mileage, fuel type, transmission)
- Find "similar vehicles" based on criteria
- Show availability status (in-stock, sold, reserved)
- Natural language queries: "Show me SUVs under $30k with low mileage"

#### Option B: Payment Estimates
- Calculate monthly payment using **only approved synthetic lender rules**
- Quote based on: vehicle price, down payment, credit tier, term length
- Show APR, total interest, total cost breakdown
- Display calculation trace with rule ID citations
- Refuse to quote when no matching rule exists

### 1.2 What is EXPLICITLY Out of Scope

| Excluded Feature | Why |
|---|---|
| Trade-in valuation | Requires external market data APIs (cost) |
| Real credit pulls (soft/hard) | Requires 700Credit/Experian integration |
| Identity verification (KYC) | Compliance complexity |
| Real lender integrations | No access to RouteOne/Dealertrack |
| Adverse action notices | Requires real credit decisions |
| Service scheduling | Different domain, adds scope |
| Multi-dealership inventory | Single synthetic dataset sufficient |

### 1.3 Unified User Journey

## 5) "Approved Lender Rules Only" Mechanism

### 5.1 Rule Selection Logic

```python
def select_lender_rule(fico_score: int, term_months: int, ltv: float) -> LenderRule | None:
    """
    Select the best matching lender rule. Returns None if no rule matches.
    
    Priority: Lowest APR among matching rules
    """
    query = """
        SELECT * FROM lender_rules
        WHERE ? BETWEEN min_fico AND max_fico
          AND ? BETWEEN min_term_months AND max_term_months
          AND ? <= max_ltv
          AND is_demo = TRUE
          AND (expiration_date IS NULL OR expiration_date >= DATE('now'))
        ORDER BY base_apr ASC
        LIMIT 1
    """
    return db.execute(query, (fico_score, term_months, ltv)).fetchone()
```

### 5.2 Payment Calculation Formula

**Standard Amortizing Loan Formula**:

```
Monthly Payment = P × [r(1+r)^n] / [(1+r)^n – 1]

Where:
  P = Principal (vehicle price - down payment + fees)
  r = Monthly interest rate (APR / 12 / 100)
  n = Number of months (term)
```

**Explicit Assumptions**:
- Simple interest, fully amortizing
- No prepayment penalties
- Fees added to principal
- Tax/title not included (disclosed)

```python
def calculate_payment(
    vehicle_price: float,
    down_payment: float,
    apr: float,
    term_months: int,
    fees: float = 0
) -> PaymentResult:
    """Deterministic payment calculation with full audit trail."""
    principal = vehicle_price - down_payment + fees
    monthly_rate = apr / 100 / 12
    
    if monthly_rate == 0:
        monthly_payment = principal / term_months
    else:
        monthly_payment = principal * (
            (monthly_rate * (1 + monthly_rate) ** term_months) /
            ((1 + monthly_rate) ** term_months - 1)
        )
    
    total_paid = monthly_payment * term_months + down_payment
    total_interest = total_paid - vehicle_price - fees
    
    return PaymentResult(
        monthly_payment=round(monthly_payment, 2),
        principal=principal,
        apr=apr,
        term_months=term_months,
        total_interest=round(total_interest, 2),
        total_cost=round(total_paid, 2)
    )
```

## 6) Agent Workflow (LLM Role + Governance)

### 6.1 What the LLM DOES

| Function | Description |
|---|---|
| **Intent parsing** | Classify user message: inventory_search, vehicle_details, payment_estimate, clarification, out_of_scope |
| **Slot filling** | Extract entities: make, model, year, price range, credit tier, down payment |
| **Tool routing** | Decide which tool/function to call based on intent |
| **Explanation** | Generate natural language explanation of results returned by tools |
| **Disambiguation** | Ask clarifying questions when input is ambiguous |

### 6.2 What the LLM must NOT DO

| Prohibited Action | Enforcement |
|---|---|
| Invent inventory | Only return vehicles from database query results |
| Invent APR/rates | Only use rates from matched lender_rules |
| Invent loan terms | Only offer terms present in matching rules |
| Make approval decisions | System provides estimates only, never "approved" language |
| Provide tax/title amounts | Out of scope, explicitly disclaimed |

### 6.3 Available Tools (Allowlisted)

```python
ALLOWED_TOOLS = [
    "search_inventory",      # Query inventory with filters
    "get_vehicle_by_id",     # Get single vehicle details
    "get_vehicle_by_vin",    # Get vehicle by VIN
    "find_similar_vehicles", # Semantic similarity search
    "estimate_payment",      # Calculate payment using lender rules
    "list_available_terms",  # Show available terms for credit tier
    "explain_calculation",   # Return calculation trace
]
```

### 6.4 Guardrails

| Guardrail | Implementation |
|---|---|
| **Allowlisted tools** | Tool calls validated against ALLOWED_TOOLS list |
| **Schema validation** | All tool inputs validated with Pydantic models |
| **Response templates** | Payment responses use structured templates with required fields |
| **Calculation verification** | Python recalculates payment before sending response; if LLM-generated number differs, correction is applied |
| **Refusal paths** | Explicit responses for out-of-scope requests |
| **Disclaimer injection** | Payment responses automatically append demo disclaimer |

### 6.5 Tool/Capability Decisions

| Component | Decision | Rationale | Fallback |
|---|---|---|---|
| **LLM (intent/generation)** | Local-first: Ollama llama3.2:8b | M4 handles 8B well, ~30 tok/s | Gemini 1.5 Flash free tier |
| **Function calling** | Custom JSON schema extraction | Simpler than LangChain for demo | LangChain if complexity grows |
| **Vector search** | Local-first: ChromaDB | Python-native, no server | FAISS if Chroma has issues |
| **Embeddings** | Local-first: nomic-embed-text | Fast on M4, good quality | sentence-transformers all-MiniLM |

### 7.3 Error Response Format

All errors follow this structure:

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "Human-readable message",
    "details": {}
  }
}
```

| Error Code | HTTP Status | Description |
|---|---|---|
| VALIDATION_ERROR | 400 | Invalid request parameters |
| VEHICLE_NOT_FOUND | 404 | Vehicle ID/VIN not in inventory |
| NO_MATCHING_RULE | 422 | No lender rule matches criteria |
| LTV_EXCEEDED | 422 | Loan-to-value ratio too high |
| INTERNAL_ERROR | 500 | Unexpected server error |

3. **Zero cost**: No API calls, no cloud services
4. **Fast iteration**: All changes are immediate, no deployment
5. **Simplicity**: Few moving parts, easy debugging

## 10) Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| **Hallucination (APR/rules)** | Medium | Critical | Deterministic calculator; LLM never generates numbers; verification layer compares LLM output to calculated values |
| **Data gaps (missing inventory attributes)** | Low | Medium | Synthetic data generation allows full control; all required fields populated |
| **Scope creep** | High | Medium | Explicitly documented out-of-scope list; declined feature requests redirect to "Phase 2" |
| **Misleading financial estimate** | Medium | High | Mandatory disclaimers; "DEMO ONLY" labels; rule_id citation in every response |
| **Local hardware limits** | Low | Medium | M4 handles 8B models well; fallback to Gemini free tier; reduce context window if needed |
| **Free-tier limits (if used)** | Low | Low | Primary stack is local-first; cloud only as fallback |
| **User trust issues** | Medium | Medium | Calculation trace shows exactly how payment was derived; transparency builds trust |
| **Stale lender rules** | Low | Low | Rules are synthetic and demo-only; effective/expiration dates in schema for future use |
